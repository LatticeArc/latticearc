Versioned detached signatures with caller-pinned verification keys. Versioned detached signatures with caller-pinned keys, algorithms and domains.

V1 signs b"LatticeArc-Detached-Signature\0" || 0x01 || algorithm_id || u16_be(domain.len()) || domain || u64_be(claims.len()) || claims. IDs: 1 = Ed25519, 2 = ML-DSA-44, 3 = ML-DSA-65, 4 = ML-DSA-87. ML-DSA uses the pure FIPS 204 mode with an empty native context. Ed25519 uses ordinary Ed25519. Neither format uses an external prehash.

Domains are 1–255 printable ASCII bytes (0x21..=0x7e). Claims are opaque bytes; JSON whitespace, field order and Unicode normalization are significant. The strict JSON record contains version, algorithm, domain and a canonical padded standard-Base64 signature. It contains neither claims nor a public key. Typed caller-supplied keys determine the algorithm; wire metadata cannot select or downgrade it. ML-DSA-65 is the default for key generation. Ed25519 is an explicit compatibility option in non-FIPS builds.

§Example

use latticearc::{CryptoConfig, generate_detached_keypair,
    sign_detached, verify_detached_with_key};
let (public_key, secret_key) = generate_detached_keypair(CryptoConfig::new())?;
let claims = br#"{"sub":"alice"}"#;
let domain = "example.com/access-token";
let signed = sign_detached(
    claims, &secret_key, domain, CryptoConfig::new(),
)?;
let valid = verify_detached_with_key(
    claims, &signed, &public_key,
    domain, CryptoConfig::new(),
)?;
