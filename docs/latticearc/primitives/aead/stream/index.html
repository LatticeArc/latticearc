Streaming AEAD: AES-256-GCM-HKDF segments (Tink-derived core) under a versioned, key-committing LatticeArc header.

§Threat model

The adversary controls every byte the decryptor reads: the header and any segment, in any order, from any stream. The guarantees are:

  • Wrong key fails before any plaintext is released. The header carries a key-commitment tag that StreamDecryptor::new verifies before a segment cipher is even derived, so a stream cannot be opened under two different keys and a wrong key never reaches AES-GCM.
  • Truncation, reordering, splicing and tampering are detected. Every segment is sealed under a nonce that encodes its index and a last-segment flag, and under per-segment associated data that binds the SHA-256 hash of the full header and the same index/flag. A segment from another stream (different key, salt or nonce prefix), a segment moved to a different index, a non-final segment presented as final, or a single flipped bit anywhere all fail authentication.
  • The 32-bit segment counter never wraps. Advancing past u32::MAX returns AeadError::SegmentCounterExhausted; the Kani harness in this module proves the increment is checked for every input.
  • Errors are opaque on the decrypt path. Header parse failures, commitment mismatch and AES-GCM tag failure all surface as the same AeadError::DecryptionFailed string, so a remote caller cannot tell which check rejected the input (design pattern 6).

Out of scope: nonce-misuse resistance (a stream key must not be reused with the same salt and nonce prefix, which the random header material makes a 2^-312 event per new), and hiding the plaintext length (segment boundaries are visible by construction).

§Construction

The segment layer is Google Tink’s AES-GCM-HKDF-STREAMING, specified at https://developers.google.com/tink/streaming-aead/aes_gcm_hkdf_streaming and implemented in https://github.com/tink-crypto/tink-java/blob/main/src/main/java/com/google/crypto/tink/subtle/AesGcmHkdfStreaming.java:

tink_header  = header_length (1 byte, = 40) || salt (32 bytes) || nonce_prefix (7 bytes)
segment_key  = HKDF-SHA256(ikm = stream key, salt = salt, info = associated data, L = 32)
nonce_i      = nonce_prefix (7) || i as u32 big-endian (4) || last_flag (1: 0x00 / 0x01)
C_i          = AES-256-GCM(segment_key, nonce_i, aad_i, M_i) || tag (16)

|C_i| == segment_size for every non-final segment, so each plaintext segment carries segment_size - 16 bytes, and the first segment is shorter by the 40-byte Tink header so that tink_header || C_0 also fills exactly one segment_size block. Tink validates this core: the tink_java_sha256_vector test reproduces the HKDF-SHA256 known-answer vector from https://github.com/tink-crypto/tink-java/blob/main/src/main/java/com/google/crypto/tink/streamingaead/internal/testing/AesGcmHkdfStreamingTestUtil.java (createTestVector2) byte for byte.

Files produced here are not Tink-interoperable, because two LatticeArc layers sit on top of that core:

header = version (1, = 0x01) || flags (1, = 0x00) || segment_size (u32 BE)
      || tink_header (40) || commitment (32)                      = 78 bytes
commitment = HMAC-SHA256(stream key, STREAM_AEAD_COMMITMENT || header[..46])
aad_i      = SHA-256(header) (32) || i as u32 BE (4) || last_flag (1)
  • The commitment follows the “UtC” shape of Bellare and Hoang, Efficient Schemes for Committing Authenticated Encryption (EUROCRYPT 2022): a PRF of the key over the public header material is stored alongside the ciphertext and checked before decryption, which turns a non-committing AEAD (AES-GCM; see Albertini et al., How to Abuse and Fix Authenticated Encryption with Key Commitment, USENIX Security 2022) into a key-committing one. HMAC-SHA256 with a 32-byte key is collision resistant in the key, so no two keys verify the same header.
  • The per-segment associated data follows the STREAM construction of Hoang, Reyhanitabar, Rogaway and Vizár, Online Authenticated-Encryption and its Nonce-Reuse Misuse-Resistance (CCS 2015): each segment is bound to the stream it belongs to and to its position in it, in addition to Tink’s nonce-level binding.

§Random access

Segment i for i >= 1 holds plaintext bytes first + (i - 1) * pss .. where first is StreamDecryptor::first_plaintext_segment_size and pss is StreamDecryptor::plaintext_segment_size; the matching ciphertext segment is at byte offset i * segment_size of the segment stream (the 78-byte header is stored separately by the caller). Callers decrypt any segment independently with StreamDecryptor::open_segment, passing is_last for the final one.
