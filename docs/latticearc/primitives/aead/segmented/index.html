Module segmented 

Source
Expand description

Fixed-geometry segmented AEAD: an object of known length is split into 64 KiB records, each sealed under its own HKDF-SHA256-derived AES-256-GCM key and authenticated against the whole object’s dimensions.

§Threat model

The adversary controls every record byte the decryptor reads. The object’s dimensions (SegmentedContext) come from caller metadata that is already authenticated by other means; they are never read from the records. The guarantees are:

  • Fixed size. Every record is exactly RECORD_LEN bytes and an object is exactly SegmentedContext::ciphertext_len bytes, so the ciphertext reveals only the record count. The last record’s plaintext is zero padded under the AEAD; the decryptor rejects nonzero padding.
  • Truncation, reordering, splicing and extension are detected. Each record’s key and associated data bind the object binding, object id, generation, plaintext length, record count, the record’s index and a final-record flag. A record moved to another index or object, or a stream cut short or extended, fails; SegmentedDecryptor::finish succeeds only after exactly every record was accepted.
  • One failure retires the handle. Any error drops (and zeroizes) the secret the encryptor or decryptor holds; it cannot be retried.
  • Errors are opaque on the decrypt path. A wrong length, wrong index, tag failure or bad padding all surface as the same AeadError::DecryptionFailed string. After that first failure the retired decryptor answers every call with AeadError::StreamExhausted; that reports the caller’s own handle state after a failure it was already told about, so it carries no information about any record.

Out of scope: confidentiality of the record count, and nonce-misuse resistance. Each record nonce is 96 random bits under a key that is unique per (secret, generation, record index), so a key never seals two records unless the caller reuses a generation; draw a fresh generation (see SegmentedContext::with_random_generation) for every object version.

Generation reuse breaks version separation. Two object versions sealed under the same secret, generation and dimensions (labels, binding, object id and plaintext length) share every record key and associated data, so a record of one version opens as the same-index record of the other: an adversary can substitute records between the versions or roll the whole object back. The all-zero generation is rejected as an unset value.

The decryptor releases each record’s plaintext as soon as it authenticates; callers must not act on the object until SegmentedDecryptor::finish succeeds and their input has ended.

§Construction

All labels are caller parameters; this module defines none.

records     = max(1, ceil(plaintext_len / 65508))
canonical_L(i) = L || binding || object_id (32) || generation (32)
              || plaintext_len (u64 BE) || records (u64 BE) || i (u64 BE)
              || final (1: 0x01 iff i == records - 1, else 0x00)
key_i       = HKDF-SHA256(ikm = secret, salt = generation,
                          info = canonical_{record_key label}(i), L = 32)
aad_i       = canonical_{record_aad label}(i)
record_i    = nonce_i (12, random) || AES-256-GCM(key_i, nonce_i, aad_i,
                                         M_i || zeros to 65508 bytes) || tag (16)

The two labels must differ and neither may be a prefix of the other, so a record-key info never equals a record’s associated data whatever the bindings; SegmentedContext::new rejects any other pair. binding is caller-defined bytes (for example a format version, a purpose code and a key identity) and is not length-prefixed: a caller must keep each (label, binding) pair unambiguous, for instance by giving every label a binding of one fixed length. derive_object_id computes SHA-256(prefix || locator) for callers that name objects by a locator.

The layout is pinned by latticearc/tests/fixtures/segmented-v1.json, generated by an independent Python HKDF-SHA256/AES-256-GCM reference implementation (scripts/generate-segmented-fixtures.py).

Structs§

SegmentedContext
Dimensions and identity of one object, from caller metadata that is already authenticated. It contains no key material.
SegmentedDecryptor
Sequential authenticating decryptor: call open_next once per record in order, then finish. Any error retires it and zeroizes the secret it holds. Plaintext returned before finish succeeds belongs to an object that is not yet known to be complete.
SegmentedEncryptor
Sequential one-use encryptor: call seal_next once per record in order, then finish. Any error retires it and zeroizes the secret it holds.
SegmentedLabels
Caller-defined domain labels; both must be non-empty.
