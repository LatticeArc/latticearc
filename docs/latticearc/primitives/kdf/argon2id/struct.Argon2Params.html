Expand description

Argon2id cost parameters.

The parameters are public protocol data (they are stored next to the salt), so this type derives Debug, Clone and PartialEq.

Fields are public for wire-format parsers; argon2id validates them on every call, so a struct built by hand cannot bypass the checks.

pub const MAX_ITERATIONS: u32 = 1024

Library cap on the number of passes.

RFC 9106 allows up to 2^32 - 1; its §4 profiles use one or three passes. The cap stops a stored parameter block from pinning a CPU for hours.

pub const MIN_OUTPUT_LEN: usize = 16

Library floor on the derived key length: 16 bytes (128 bits).

RFC 9106 §3.1 permits tags as short as 4 bytes, but §4 step 8 names 128 bits as the length that suffices for key derivation. Shorter keys are rejected.

pub fn validate(&self) -> Result<()>

Check the parameters against RFC 9106 §3.1 and the library bounds.

Checks, in order:

  • parallelism in Self::MIN_PARALLELISM..=Self::MAX_PARALLELISM
  • memory_kib >= 8 * parallelism
  • iterations in Self::MIN_ITERATIONS..=Self::MAX_ITERATIONS
  • output_len in Self::MIN_OUTPUT_LEN..=Self::MAX_OUTPUT_LEN

The memory cap from resource limits is checked separately by argon2id, because it can change at runtime.

§Errors

Returns LatticeArcError::InvalidParameter naming the first failed check.

Source

pub fn calibrate(target_ms: u64, max_memory_kib: u32) -> Result<Self>

Measure Argon2id on this machine and pick parameters that take about target_ms milliseconds per derivation.

Follows the procedure in RFC 9106 §4: memory first, then passes. With parallelism = 1 and a 32-byte output, it starts at Self::CALIBRATION_START_MEMORY_KIB and one pass, doubles the memory until it reaches the cap or a run exceeds the target, and then sets the pass count from the measured one-pass time, rounding down so the estimate stays within the target.

The memory cap is the smaller of max_memory_kib and the max_argon2_memory_kib resource limit, so the result is always accepted by argon2id under the current limits.

The result is machine- and load-dependent. Calibrate once at provisioning time and store the parameters with the salt; do not recalibrate when verifying, or the derived key changes. If even the first run exceeds the target, the first run’s parameters are returned.

Memory doubles geometrically and the run that overshoots costs at most about twice the target, so calibration takes roughly three times target_ms plus the first run.

§Errors

Returns LatticeArcError::InvalidParameter if target_ms is zero or above Self::MAX_CALIBRATION_TARGET_MS, or if the effective memory cap is below Self::MIN_MEMORY_KIB_PER_LANE. Propagates any error from the measurement runs.

impl Default for Argon2Params

Source§

fn default() -> Self

Mobile-friendly profile: 64 MiB, 3 passes, 1 lane, 32-byte key.

Memory and passes match the RFC 9106 §4 SECOND RECOMMENDED option (t = 3, m = 2^16 KiB), which the RFC gives for systems with much less memory than the 2 GiB first option; 64 MiB fits phones and small containers. The RFC option uses p = 4; this profile uses p = 1 because lanes run sequentially in this build (see the module docs), so extra lanes add no defender throughput. The 32-byte output is a 256-bit key. Use Argon2Params::calibrate to tune for a specific machine.
