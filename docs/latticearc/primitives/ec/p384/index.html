§ECDSA over NIST P384 with SHA-384 (verify only)

Verification of ECDSA P384 / SHA-384 signatures (FIPS 186-5) produced by third parties, for interoperability with signed formats such as JWS (ES384, fixed-width r || s), COSE, and X.509 certificate chains (ASN.1 DER Ecdsa-Sig-Value). Backed by aws-lc-rs.

§Result convention

  • The public key must be the 97-byte uncompressed SEC1 encoding (0x04 || X || Y) of a point on the curve; any other length, the compressed form, or an off-curve point is an Err. The key is checked before anything else.
  • A signature of impossible length is an Err: fixed-width signatures must be exactly 96 bytes, DER signatures 1 to P384_MAX_DER_SIGNATURE_LEN bytes.
  • A message longer than the signature resource limit (max_signature_size_bytes, 64 KiB by default) is an Err.
  • Otherwise the call returns Ok(true) for a valid signature and Ok(false) for any signature that does not verify, including a DER value that does not parse.

§FIPS

ECDSA P384 / SHA-384 verification over a message is a FIPS 186-5 approved service of the aws-lc-rs module. The _prehash variants verify a caller-supplied digest; aws-lc-rs does not list digest verification as an approved service, so they are documented as non-approved in docs/FIPS_SECURITY_POLICY.md.
