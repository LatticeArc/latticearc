ECDSA P-256 / SHA-256 signature verification (FIPS 186-5), verify only.

§ECDSA over NIST P256 with SHA-256 (verify only)

Verification of ECDSA P256 / SHA-256 signatures (FIPS 186-5) produced by third parties, for interoperability with signed formats such as JWS (ES256, fixed-width r || s), COSE, and X.509 certificate chains (ASN.1 DER Ecdsa-Sig-Value). Backed by aws-lc-rs.

§Result convention

  • The public key must be the 65-byte uncompressed SEC1 encoding (0x04 || X || Y) of a point on the curve; any other length, the compressed form, or an off-curve point is an Err. The key is checked before anything else.
  • A signature of impossible length is an Err: fixed-width signatures must be exactly 64 bytes, DER signatures 1 to P256_MAX_DER_SIGNATURE_LEN bytes.
  • A message longer than the signature resource limit (max_signature_size_bytes, 64 KiB by default) is an Err.
  • Otherwise the call returns Ok(true) for a valid signature and Ok(false) for any signature that does not verify, including a DER value that does not parse.

§FIPS

ECDSA P256 / SHA-256 verification over a message is a FIPS 186-5 approved service of the aws-lc-rs module. Under --features fips the AWS-LC FIPS module rejects two valid Wycheproof P-256 signatures (with s = 2^128 and s = n - 2^128) that the default backend accepts; that is a false reject, never a false accept. The _prehash variants verify a caller-supplied digest; aws-lc-rs does not list digest verification as an approved service, so they are documented as non-approved in docs/FIPS_SECURITY_POLICY.md.
