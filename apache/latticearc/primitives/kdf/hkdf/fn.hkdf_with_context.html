Expand description

HKDF with a required, non-empty context as the RFC 5869 info input.

Identical to hkdf(ikm, salt, Some(context), length) except that an empty context is rejected: every key derived through this entry point is bound to an application label such as b"vault/v1/inbox", so two callers sharing ikm and salt can never derive the same key by omitting the label. Different contexts yield independent outputs.

Planned deprecation (0.14): hkdf with info = None. Not attributed in 0.13 because many crate-internal call sites still use the optional form.

§Errors

Returns InvalidParameter if context is empty, and the same errors as hkdf otherwise (empty IKM, explicit empty salt, bad length).
