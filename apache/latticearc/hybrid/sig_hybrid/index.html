Hybrid Digital Signatures Module

This module provides hybrid digital signatures that combine post-quantum (ML-DSA) and classical (Ed25519) signature algorithms for enhanced security during the quantum transition period.

§Security Properties

  • EUF-CMA (Existential Unforgeability under Chosen Message Attack) security
  • AND-composition: Requires breaking BOTH ML-DSA AND Ed25519 to forge
  • Automatic memory zeroization for secret keys via ZeroizeOnDrop

§Transcript modes

Every hybrid signature binds a per-scheme label into both legs (the “H1 / M1” transcript fix). 0.13 adds two further modes, each with its own label family so no signature from one mode verifies under another, even if one leg is broken:

ModeEntry pointsML-DSA legEd25519 leg
plainsign / verifyML-DSA.Sign(M, ctx = LABEL)Ed25519(SHA-512(LABEL ‖ 0x00 ‖ M))
contextsign_with_context / verify_with_contextML-DSA.Sign(M, ctx = LABEL-ctx ‖ 0x00 ‖ app_ctx)Ed25519(SHA-512(LABEL-ctx ‖ 0x00 ‖ ‖app_ctx‖ ‖ app_ctx ‖ M))
pre-hashedsign_prehashed / verify_prehashedHashML-DSA.Sign(SHA-512(M), ctx = LABEL-ph ‖ 0x00 ‖ app_ctx)Ed25519ph(SHA-512(M), ctx = LABEL-ph ‖ 0x00 ‖ app_ctx)

The context and pre-hashed modes require a non-empty application context of at most MAX_HYBRID_SIG_CONTEXT_LEN bytes. The pre-hashed mode takes a caller-computed SHA-512 digest, so content of any size can be signed without the 64 KiB message cap that bounds the other two modes. generate_keypair_from_seed derives both legs from one 32-byte seed.

§Example

use latticearc::hybrid::sig_hybrid::{generate_keypair, sign, verify};

// Generate hybrid keypair
let (pk, sk) = generate_keypair()?;

// Sign a message (deterministic - no RNG needed)
let message = b"Hello, hybrid signatures!";
let signature = sign(&sk, message)?;

// Verify the signature
let is_valid = verify(&pk, message, &signature)?;
assert!(is_valid);
